1. 프로젝트 전체 목표 (사용자가 원하는 것)
================================================================================

  음악을 검색하면 곡 정보, 구체적인 장르, 비슷한 음악 추천을 받을 수 있는
  웹 앱. 이후 요청들은 모두 "검색·추천·장르 탐색 경험을 더 정확하고 직관적으로
  만든다"는 방향으로 수렴했다.

  핵심 기대:
    - 검색하면 원곡(오피셜)이 먼저, 정확도 순으로 나온다
    - 한글·영문·혼합 입력 모두 원명(영문 canonical) 기준으로 동작한다
    - 장르 맵에서 여러 장르를 고르면 AND 조건으로 맞는 곡만 추천한다
    - 국가 필터는 추천/검색 결과만 거르고, 장르 맵 자체는 망가지지 않는다
    - AI 추천 설명과 유사도 %가 무엇을 의미하는지 이해할 수 있다
    - UI에서 선택·활성 상태가 한눈에 보인다

[A] 초기 구축 — 음악 검색·장르·유사곡 프로그램
--------------------------------------------------------------------------------
  요청: "궁금한 음악을 검색하면 그 음악 정보랑 구체적인 장르, 비슷한 음악
        추천해주는 프로그램 만들어줘"

  원하는 기능:
    - 통합 검색, 곡 상세, 장르 표시, 유사곡 추천
    - Last.fm · MusicBrainz · Deezer · Spotify · YouTube Music 등 연동

  조치:
    - FastAPI 백엔드 + React(Vite) 프론트 구축
    - Every Noise 장르 맵, 유사도 점수, GPT recommendation_reason 등 점진 확장

[J] 검색 결과 정확도
--------------------------------------------------------------------------------
  요청: "검색 결과가 좀 이상한데, 정확도 순으로 잘 나오는거 맞아?"

  문제:
    - 국가 선택 시 korean 태그가 검색어에 섞여 무관한 인기곡 유입
    - relevance가 느슨해 fan upload(제목에만 단어 포함)가 원곡과 비슷한 점수
    - 인기도 28% 비중으로 엉뚱한 곡 상위 노출

  조치:
    - 국가 태그는 필터 전용, catalog 검색 pool에 merge 안 함
    - _search_relevance: title/artist 교차 매칭, fan upload·live/cover 감점
    - 인기도 비중 28% → 15%
    - 커밋: 7f32e59

[K] 오피셜 곡 우선
--------------------------------------------------------------------------------
  요청: "오피셜 노래 우선으로 올려"

  문제:
    - YouTube/SoundCloud 단독 hit가 인기만으로 official 처리
    - enrich 후 deezer_id 확보해도 재정렬 안 됨
    - fan upload(제목에 Artist - Title)가 official로 분류

  조치:
    - _is_official_search_hit 강화: catalog ID / Last.fm·MB·Deezer·Spotify만 official
    - YT/SC 단독 → 비오피셜, _official_rank 3단계 정렬
    - metadata enrich 후 is_official 재계산 + 재정렬
    - 커밋: c2fda8f (이전 c16f704에서 1차 official sort 도입)
